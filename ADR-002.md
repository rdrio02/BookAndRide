# ADR-002: Database Schema Design


The system manages **books** and **bike rentals**.  
We need a data model that maintains relational integrity, supports transactional consistency, and enables integration with Elasticsearch for analytics.

## Decision
We use **PostgreSQL** as the main data store and **SQLAlchemy ORM** to define models.

### Tables

#### Book
| Column | Type | Description |
|--------|------|-------------|
| id | Integer | Primary key |
| title | String | Book title |
| author | String | Author name |
| stock | Integer | Number of available copies |

#### Rental
| Column | Type | Description |
|--------|------|-------------|
| id | Integer | Primary key |
| user_id | Integer | ID of the user renting the bike |
| bike_id | String | Unique bike identifier |
| started_at | DateTime | Start time of rental |
| stopped_at | DateTime (nullable) | Stop time of rental |
| total_minutes | Integer | Duration of rental |
| price_eur | Float | Price of rental in euros |

## Alternatives Considered
- **NoSQL (MongoDB):** Easier schema evolution, but poor relational support.
