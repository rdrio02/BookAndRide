# ADR-001: Architecture Choice

We needed to design a lightweight yet extensible API system for managing **book data** and **bike rentals**, with search functionality, monitoring, and containerized deployment.  
The architecture must support both **transactional operations** (renting, returning) and **search queries** efficiently.

## Decision
We chose a modular monolithic architecture built around **FastAPI** for simplicity and performance.  
The system is composed of several independent but connected components:

- **FastAPI** → Main REST API service  
- **PostgreSQL** → Primary relational database for persistent structured data  
- **Elasticsearch** → Secondary store for full-text search and analytics  
- **Prometheus** → Monitoring and metrics collection  
- **Nginx** → Reverse proxy for routing and load handling  
- **Docker Compose** → Simplified orchestration for local development
